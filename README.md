# 仓内作业分析

从扫码流水、作业单和仓库拓扑还原仓内作业：**哪个人、在什么时间、位于哪个通道**；
在通道容量口径下统计同时占用与超容量区间；并对比两套发单顺序的回放结果。

项目从零实现，只依赖 Python 3.11 标准库与原生 ES Module，无构建步骤、无外部服务。
数据全部为本地合成，覆盖重复扫码、任务取消（发单前 / 取货中途）、设备离线与拓扑改版。

## 快速开始

```bash
python3 scripts/build_data.py          # 重新生成 data/（已附带生成结果，可跳过）
python3 -m src.warehouse.server        # http://127.0.0.1:8765/
```

`data/dataset.json` 不存在时服务会自动生成。运行测试：

```bash
python3 -m unittest discover -s tests -v
```

> 数据、页面与接口均在本地；导入的文件只在内存中解析，不会上传到任何外部服务。

## 分析方法

### 1. 从扫码到位置分层

扫码只提供“某人在某时刻扫了某货位”的观测点，不等于连续定位。推断把每个时间段分为四层，
并在页面上分别着色、可分别开关：

| 层 | 含义 | 证据 |
|---|---|---|
| 确切驻留 `dwell` | 同一货位连续扫码之间的驻留 | 观测 |
| 可能区间 `possible` | 两次扫码之间，按最短路与行走速度只能确定“可能在这里” | 推测 |
| 扫描缺口 `gap` | 间隔显著超过预计步行时间，提示确认扫码缺失或设备离线 | 推断 |
| 位置未知 `unknown` | 超过 `long_gap_s` 仍无扫描；不会继续算在最后货位 | 无证据 |

关键规则：

- 相邻扫码在不同货位时，先给出 `dwell_min_s` 的最短驻留，再按最短路 / `walk_speed_mps`
  计算最早到达与最晚离开，中间只能是 `possible`，不能标成驻留。
- 间隔超过 `long_gap_s`（默认 420 秒）时，驻留只保留最短下限，其余整段标为 `unknown`。
- 重复扫码（`repeat` / 短间隔内同货位 `confirm`）会合并，并保留 `kept → dropped` 审计记录。
- 旧货位条码通过拓扑 `aliases` 解析到当前货位，历史事件仍按当时区域解释。

行走速度不必手工拍板：参数面板用相邻不同货位扫码的间隔做 Theil–Sen 稳健回归，
给出建议速度与平均驻留，可一键采用后重算。

### 2. 通道容量与冲突成因

对每个通道按扫描线统计每个基本区间的**观测人数**与**推测人数**：

- 观测人数 > 容量 → `confirmed`（确证重叠）；
- 叠加推测后才 > 容量 → `possible`（推测重叠）。

每段超容量区间给出**多标签的候选成因**，并各自附“替代解释”：

- `task_cross`：观测到的人来自不同区域或不同发单波次，属于发单节奏造成的交汇；
- `data_gap`：区间内有扫描缺口，占用时长可能被拉长；
- `possible`：人数叠加依赖推测区间。

页面明确写出**相关不等于因果**：同一通道人多可能是任务分配、扫描缺失或推测叠加，
成因是候选解释而不是判决。冲突行可展开查看涉及人员、作业单（含取消状态）、判定依据与替代解释，
并可一键在平面图中定位该时刻。

### 3. 两套发单顺序回放

同一批作业单、同一批人员，仅改变发单顺序/节奏：

- 方案 A：同区成组、按波次集中发单；
- 方案 B：快拣/冷链交替、跨区混流发单。

并排回放同一时刻的平面图，对比冲突区间数、冲突时长、行走距离与未知时长。
页面只报差异，不宣称因果，并列出“冲突少不代表更好”“未知比例不同不可直接横比”等读数注意事项。

### 4. 合成数据中的“脏”

`data/dataset.json` 的两个场景刻意包含：

- 重复扫码（`repeat` 指向原始 `scan_id`，或同货位短间隔 `confirm`）；
- 发单前取消（不产生扫码）与取货中途取消（保留已发生扫码，之后折返）；
- P05 在 11-12 场景中约 15 分钟设备离线（产生 `data_gap`，而非“无人”）；
- 拓扑改版：C 通道容量 2→1、A 通道 2→3、D 通道划入冷链区、`STG-02` 条码改为 `STG-02N` 并保留别名。

`calibration` 接口用仿真真值检验推断（驻留归属、未知召回、陈旧位置占比、冲突时长上下限），
仅在合成数据上显示；导入的真实数据没有真值，不显示校准指标。

## 目录

```
src/warehouse/
  models.py      数据模型与时间解析
  topology.py    拓扑加载、别名解析、步道最短路
  synth.py       合成数据生成（拓扑 v1/v2、场景、回放、CSV）
  inference.py   位置分层、去重、容量冲突与成因
  eval.py        校准指标与行走速度回归
  ingest.py      CSV/JSON 导入适配
  server.py      HTTP API 与静态页面
web/             原生 ES Module 前端（SVG 平面图、图表、表格视图）
data/            生成的数据与 CSV 样例（导入面板可直接试用）
tests/           推断、生成器、导入与 HTTP 接口测试
scripts/build_data.py  重新生成数据
```

## 导入自己的数据

在“数据导入”页选择三个文件（或点“载入内置样例说明”直接用 `data/csv/` 的文件）：

- `topology.json`：实体、容量、货位、步道节点与边、别名；
- `scans.csv`：`scan_id, ts, picker, location, task, device, source, kind, duplicate_of, note`；
- `tasks.csv`：`task_id, zone, released_at, cancelled_at, order_ids, locations` 等。

时间列支持 ISO8601（含时区）或 epoch 秒。格式详见 `data/csv/README.txt`。
